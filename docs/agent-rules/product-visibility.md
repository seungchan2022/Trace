# Product Visibility Rules

사용자가 상세 구현 문서를 읽지 않아도 Trace의 제품 방향과 현재 MVP 상태를 이해하도록 하는 규칙이다.
AI 구현의 정본과 사용자용 요약을 분리해, 현황판이 구현을 방해하거나 별도 체크리스트가 되지 않게 한다.

## 문서 역할

- `docs/product-baseline.md`: 현재 제품 문제·약속·기둥·원칙의 정본이다. 기능 목록이나 구현 상세를 넣지 않는다.
- `docs/current-features.md`: 현재 사용자가 할 수 있는 일을 사용자 시나리오 순서로 정리한 사실 원본이다.
  현재 제공·조건부·확인 필요 상태와 근거 링크를 담고, 포트폴리오 최종 문구는 별도로 작성한다.
- `docs/current-features.html`: 위 문서의 시각판이다. 사용자 흐름을 그림으로 먼저 보여주고
  번호로 항목 목록과 잇는다. **정본이 아니다** — 내용이 어긋나면 `current-features.md`를 따르고,
  그 문서를 갱신할 때 이 파일도 함께 본다. 브라우저는 Chrome으로 연다.
- `docs/current-mvp.md`: 사용자가 현재 MVP를 이해하고 확인할 일을 찾는 현황판이다. 저장소에 항상 존재한다.
- 구현 요구사항과 진행 상태의 정본은 `docs/superpowers/specs/`, `docs/superpowers/plans/`,
  `docs/roadmap.md`, `docs/qa/`다. 충돌하면 이 정본을 따르고 현황판을 고친다.

## 활성 MVP 현황판

진행 중인 MVP가 있으면 `docs/current-mvp.md`는 다음을 제품 언어로 요약한다.

- 왜 만드는가와 사용자가 겪게 될 변화
- 이번 MVP에서 하지 않는 것
- 현재 단계와 마일스톤 진행 요약
- 사용자가 내린 제품 결정과 아직 확인할 결정
- 빌드·테스트·실기기에서 확인된 결과
- 사용자가 다음에 확인할 것
- 제품 기준선 영향: `없음` / `변경 후보` / `변경 확정`
- 마지막 갱신일과 근거 문서 링크

코드 파일, 함수 시그니처, 구현 Task, 커밋별 진행은 복사하지 않는다.

진행 중인 MVP가 없으면 현재 상태, `product-baseline.md`, `current-features.md`, 마지막 완료 MVP,
`docs/backlog.md` 링크만 둔다.

새 MVP를 스코핑할 때는 `current-features.md`를 확인해 이미 제공 중인 사용자 경험, 조건부 기능,
확인되지 않은 기능과 후보 범위가 겹치는지 먼저 대조한다. 이 확인은 기능 아이디어를 막는 승인이 아니라
중복 구현과 현재 상태 오해를 피하기 위한 입력이다.

## 갱신 경계

현황판은 다음 네 시점에만 갱신한다.

1. MVP를 roadmap에 등록하고 킥오프를 마쳤을 때
2. 마일스톤을 닫고 roadmap을 갱신했을 때
3. 실기기 QA 결과를 사용자가 수용했을 때
4. MVP를 완료하고 아카이빙할 때

Task·커밋·코드리뷰마다 갱신하지 않는다. 사용자 확인이 필요한 제품 결정이 없으면 현황판 때문에
구현을 멈추지 않는다.

`docs/current-features.md`는 마일스톤 실기기 QA 결과를 사용자가 수용했을 때 해당 사용자 흐름만
갱신한다. MVP 아카이빙 때 누락 여부를 마지막으로 확인하되, 과거 변경 이유는 완료 회고를 링크하고
기능 문서에 복사하지 않는다.

## 제품 기준선 변경

- 마일스톤 결과가 제품 문제·대상·약속·기둥·원칙을 바꿀 가능성이 있을 때만 `변경 후보`로 표시한다.
- 후보를 제품 기준선에 자동 반영하지 않는다. MVP 완료 시 사용자 승인을 받은 경우에만
  `product-baseline.md`를 갱신한다.
- 이전 방향과 변경 이유는 완료 회고에 남긴다.

## 완료와 아카이빙

`trace-archive`는 최신 현황판을 `history/mvpN/overview.md`로 보존하고,
`docs/current-mvp.md`를 진행 중 MVP 없음 상태로 다시 만든다. 완료 기록을 소급해 현황판으로 만들지 않는다.

## 노출과 정합성

- `trace-init`은 `current-mvp.md`를 먼저 읽고 현재 MVP·단계·사용자 결정·다음 확인 항목을 보여준다.
- 현황판과 roadmap이 다르면 stale 상태로 보고한다. `trace-init`은 읽기 전용이므로 자동 수정하지 않는다.
- 사용자 대화에서는 MVP 킥오프, 구현 시작, 마일스톤 종료, 실기기 QA 요청, MVP 완료 시에만
  현황판 링크를 다시 안내한다.
