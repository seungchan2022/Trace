# 에이전트 규칙 정리 — 중복 걷어내기 + trace-init 경량화

> **For agentic workers:** 이 파일은 **학습(`trace-study`)이 아니라 규칙·스킬 정리 작업**이다.
> `/trace-init`이 체크박스를 읽어 다음 Task를 복원한다. **학습 재개보다 이 작업이 먼저다**
> (근거는 아래 「왜 학습보다 먼저인가」).

**Goal:** 학습을 진행하며 여러 곳에 흩어져 쌓인 규칙에서 **중복을 걷어내고, 정본을 한 곳으로 모으고,
`/trace-init`이 매 세션 먹는 컨텍스트를 줄인다.**

**착수 배경(2026-08-24):** 사용자 지적 — *"규칙들이 처음보다 너무 길어졌기도 하고 같은 내용이
여러번 들어간것들도 있을거야. 내가 너가 자꾸 실수 하니까 계속 넣으라고 했거든. 그런데 …
너무 많은 내용에 대한 스킬은 오히려 제대로 적용이 안되고 짧은 형태로 여러개 나눠서 인덱스 형태로
해당 작업을 참조하도록 하거나 같은 내용을 여러번 넣을 필요가 없다고 하더라고."*

## 왜 학습보다 먼저인가

같은 날 **학습 깊이를 내리는 결정**을 했고(`.agents/skills/trace-study/decision-log.md`),
`SKILL.md`와 메모리 두 건은 이미 고쳤다. **그런데 같은 말이 아직 세 곳에 흩어져 있어서,
한 곳만 고치면 나머지가 옛 규칙으로 계속 적용된다.** 실제로 오늘 메모리에 *"목표는 C"*가
그대로 남아 있는 것을 발견했다 — 안 고쳤으면 다음 학습 세션이 옛 깊이로 돌아갔다.

## 정리 원칙 (2026-08-24 합의)

> **스터디 밖에서도 적용되는 것** → **메모리가 정본**, `SKILL.md`에서는 뺀다
> **스터디 안에서만 적용되는 것** → **`SKILL.md`가 정본**, 메모리에서 뺀다
> 양쪽에 필요하면 **한쪽은 포인터 한 줄만**

메모리 본문에 *"스터디 밖에서도 적용된다(사용자가 명시했다)"*가 붙은 것들이 있어 대부분 그 표시로 갈린다.
**애매하면 지우지 말고 사용자에게 묻는다** — 규칙 하나하나가 값을 치르고 생긴 것이다.
