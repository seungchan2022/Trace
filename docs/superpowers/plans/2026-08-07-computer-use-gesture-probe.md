## 무엇을 알아내려는가

**XcodeBuildMCP가 못 하는 "누른 채 이동"을 computer-use가 할 수 있는가.**

- 막힌 이유는 기록돼 있다 — `docs/solutions/workflow-issues/xcodebuildmcp-cannot-synthesize-long-press-drag.md`.
  시뮬레이터 터치 합성 API가 `touch move`를 지원하지 않아 **네 프리미티브 전부 실패**했다.
- **computer-use는 그 API를 안 거친다.** macOS 마우스 이벤트를 시뮬레이터 창에 직접 보내고,
  `left_mouse_down` · `mouse_move` · `left_mouse_up`을 **따로** 부를 수 있어 구조상 "누른 채 이동"이 만들어진다.
- ⚠️ **이건 추론이다. 확인된 바 없다.**

성공하면: 그리기 제스처를 **실기기 없이** 확인할 수 있게 된다(지금은 실기기 QA가 유일한 경로).

## 절차

### 1. 권한

`request_access(["Simulator"])`. 실패하면 위 🔴로 돌아간다 — **재시도로는 절대 안 뚫린다.**

⚠️ Simulator가 어느 tier로 잡히는지 **확인되지 않았다.** 개발 도구라 "click" tier(클릭만 허용,
드래그 차단)일 가능성이 있다. `left_mouse_down`이 거부되면 **그 사실 자체가 결론**이다 — 기록하고 끝낸다.

### 2. 화면 잡기

`screenshot`으로 시뮬레이터 창 위치를 확인하고 **지도 영역의 좌표**를 읽는다.
시뮬레이터가 안 보이면 `open_application("Simulator")`.

### 3. 그리기 모드로 전환

상단 **「그리기」** 버튼을 `left_click`. 스크린샷으로 모드가 바뀐 것을 확인한다.

### 4. 본 검증 — 누른 채 이동

**`computer_batch` 하나로 보낸다**(round-trip 사이에 시간이 흐르면 판정이 흐려진다):

```
mouse_move        → 지도 위 시작점
left_mouse_down
wait 0.4          ← 임계값 0.25초보다 크게
mouse_move        → 중간점 1
mouse_move        → 중간점 2
mouse_move        → 중간점 3
left_mouse_up
screenshot
```

**중간점을 여러 개 두는 것이 핵심이다.** 한 번에 끝점으로 점프하면 이동 이벤트가 하나뿐이라
스트로크가 안 쌓일 수 있다.

### 5. 판정

| 결과 | 뜻 |
|---|---|
| **경로 선이 그려짐** | ✅ 성공 — 앞으로 그리기 제스처를 시뮬레이터로 검증할 수 있다 |
| **지도만 움직임** | ❌ 롱프레스가 인식되지 않았다(XcodeBuildMCP `swipe`와 같은 실패) |
| **아무 일도 안 일어남** | ❌ 이벤트가 시뮬레이터에 도달하지 못했다 |
| **도구가 거부** | ❌ tier 제한 — 구조적으로 불가 |

**애매하면 `mcp__XcodeBuildMCP__screenshot`으로 앱 화면을 직접 찍어 대조한다**(computer-use
스크린샷은 창 전체라 선이 잘 안 보일 수 있다).

### 6. anti-loop — 이 선을 지킨다

**각 가설은 1회씩만 시도한다.** 실패 시 조정해볼 것은 **아래 둘까지만**이고, 그 뒤에는 멈춘다.

1. `wait` 시간을 0.4 → 0.6으로
2. 중간 `mouse_move`를 3개 → 6개로

**그래도 안 되면 "computer-use로도 불가"로 판정하고 끝낸다.** 조합을 늘려가며 루프를 돌지 않는다 —
앞 사이클이 정확히 그러다 시간을 날렸고 그것이 저 solutions 문서가 쓰인 이유다.
