# Trace 현재 기능 전수 문서 — 다음 세션 재개 지점

> **상태: 방향 확정 대기**
> 이 파일은 구현 계획이 아니라 Codex와 Claude Code가 다음 세션에서 같은 지점부터 시작하기 위한 진행 상태다.

## 목표

현재 Trace에서 사용자가 실제로 이용할 수 있는 기능을 한눈에 확인하는 문서를 만든다.
`product-baseline.md`의 제품 방향, `current-mvp.md`의 활성 작업 현황과 역할이 겹치지 않아야 한다.

## 왜 다음 세션에서 먼저 방향을 정하나

아직 문서의 주 독자, 기능을 나누는 크기, 완료·실험·폐기 기능의 표시 방식, 최종 위치를 확정하지 않았다.
이를 정하지 않고 기능부터 나열하면 포트폴리오 문구·코드 목록·MVP 연대기가 한 파일에 섞일 수 있다.

## 다음 세션 첫 작업

🔴 **`trace-init`으로 이 작업을 복원한 뒤, 문서를 쓰기 전에 `superpowers:brainstorming`으로 방향을 정한다.**
한 번에 하나씩 질문하고, 사용자가 방향을 승인하기 전에는 기능 전수나 초안 작성을 시작하지 않는다.

먼저 합의할 항목:

1. 주 독자와 용도 — 제품 이해·관리용 / 포트폴리오 근거용 / 둘을 연결하는 원본
2. 기능 단위 — 화면 / 사용자 흐름 / 사용자가 얻는 능력
3. 포함 범위 — 현재 동작만 / 실험·조건부 기능 포함 / 교체·폐기 기능의 기록 위치
4. 기능별 필드 — 사용자 장면, 제공 가치, 현재 상태, 확인 근거 중 무엇을 남길지
5. 파일 이름·위치와 이후 MVP에서 갱신할 시점

위 항목은 질문 목록이지 결정된 형식이 아니다.

## 방향 확정 뒤 할 일

- [ ] 문서의 독자·목적·기능 단위·포함 범위·갱신 규칙을 사용자와 확정한다.
- [ ] 현재 checkout의 화면·사용 흐름·테스트와 `history/INDEX.md`를 대조해 현재 기능 범위를 수집한다.
- [ ] 교체·삭제된 과거 기능을 현재 기능과 분리하고, 불확실한 항목은 검증 상태로 표시한다.
- [ ] 합의한 위치에 전수 기능 문서를 작성하고 `product-baseline.md`에서 찾을 수 있게 연결한다.
- [ ] Codex `$trace-init`과 Claude Code `/trace-init`에서 다음 MVP 시작을 방해하지 않는지 확인한다.

## 제한

- 코드 파일·함수 목록이나 구현 학습 노트를 만들지 않는다.
- 포트폴리오 최종 문구를 이 문서에서 확정하지 않는다.
- 과거 MVP 문서만 보고 현재 동작이라고 단정하지 않는다. 현재 checkout 또는 실행·테스트 근거와 대조한다.
- 새 MVP 개발 범위를 이 문서 작업에서 정하지 않는다.
