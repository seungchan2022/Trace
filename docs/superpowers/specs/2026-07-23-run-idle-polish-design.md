# run-idle-polish 설계 보정 (MVP17 마일스톤 2)

## 결정 요약

MVP17 `history-tab` 실기기 QA(2026-07-23) 결과, 러닝 탭에 넣은 이번 주/지난 러닝 한 줄은 대기 화면의 목적을 설명하지 못했다. 러닝 탭은 기록을 돌아보는 곳이 아니라 **러닝 전에 목표를 정하고 바로 시작하는 곳**으로 확정한다. 기록·집계·최근 러닝은 `기록` 탭만 소유한다.

이 문서는 MVP17 킥오프 스펙의 §7·§7.1·§7.2를 보정한다. 새 MVP를 만들거나 `history-tab` 범위에 대기 화면 재설계를 섞지 않는다. 이미 예정된 다음 마일스톤 `run-idle-polish`의 설계 입력이다.

## 실기기 QA 기록

### 통과

- 세션 1: GPX로 러닝 시작·종료·저장, 러닝 탭 요약 갱신, 기록 목록·집계·그래프 반영이 정상 동작했다.
- 큰 글자 크기에서도 기록 탭 콘텐츠가 잘리거나 겹치지 않았다.

### 발견

1. **기록 탭 다크 모드 대비 부족** — 시스템 `List` 배경이 거의 검정으로 보이고, 최근 8주 그래프의 수평 격자선이 읽기 어려웠다. 이는 `history-tab`의 QA 실패이며, 마일스톤 2와 별개로 현재 마일스톤의 작은 보정 태스크가 소유한다.
2. **VoiceOver 검증 우선순위 제외** — 이번 MVP의 실기기 QA 완료 조건에서 제외한다. 기존 접근성 표시는 유지해도 되지만, 추가 구현·검증을 요구하지 않는다.
3. **러닝 탭 대기 화면의 처방 실패** — 이번 주 거리·횟수 한 줄은 화면의 목적을 강화하지 못했고, 첫 화면에서 왜 있는지 이해되지 않았다.
4. **잘못된 초기 문구** — 앱 재실행 직후 공유 기록이 아직 로드되지 않아도 "첫 러닝을 시작해보세요"를 표시하고, 기록 탭 방문 후 같은 화면이 이번 주 실적으로 바뀌었다. 이는 비어 있는 데이터와 아직 읽지 않은 데이터를 구별하지 않은 결함이다.

## 제품 방향

### 러닝 탭의 한 가지 질문

대기 화면은 **"지금 어떤 러닝을 시작할까?"**에 답한다. 따라서 첫 화면에서 사용자가 보는 순서는 아래 하나로 고정한다.

1. `오늘의 러닝` — 자유·거리·시간 중 하나를 고른다.
2. 선택한 목표 — 거리 또는 시간 입력값을 확인·수정한다. 자유를 고르면 추가 입력은 없다.
3. `시작` — 화면의 가장 강한 행동이며, 목표 설정 뒤에 즉시 실행한다.

기록 수·이번 주 합계·지난 러닝·격려 문구는 러닝 탭에서 표시하지 않는다. 사용자가 지난 활동을 보고 싶으면 하단 `기록` 탭으로 간다. 이는 "지금 뛴다 / 돌아본다" 역할 분담을 화면에도 그대로 적용하는 결정이다.

### 상태와 데이터 소유권

- 대기 화면은 기존 `RunGoalMode`와 목표 입력 상태만 소비한다.
- 러닝 탭은 `RunHistoryViewModel`을 읽지 않는다. 따라서 기록을 아직 불러오지 않았는데 "첫 러닝"이라고 단정하거나, 탭 방문 뒤 문구가 바뀌는 일이 구조적으로 사라진다.
- 저장 성공 뒤 기록 목록의 최신화는 기존 공유 기록 스토어 흐름을 유지한다. 단, 러닝 탭은 그 비동기 갱신을 화면 상태로 사용하지 않는다.

### 현재 `history-tab` 보정 (별도 태스크)

이 두 항목은 `run-idle-polish` 범위가 아니라, 현재 `history-tab` 마일스톤에 추가할 QA 보정 태스크가 다룬다.

- 기록 탭 목록의 시스템 기본 검정 배경을 쓰지 않고, DesignToken의 어두운 표면색을 화면 전체에 명시적으로 적용한다.
- 차트 수평 격자선은 일반 `Border` 토큰의 낮은 투명도를 재사용하지 않고, 다크 모드에서 거리 눈금이 보이는 전용 대비 스타일을 쓴다. 막대·텍스트보다 약하지만 배경에 묻히지 않아야 한다.

색상 수정은 기록 탭에 한정한다. 앱 전체 색 토큰을 일괄 변경하거나 차트 기능을 추가하지 않는다.

## 범위와 비범위

### 포함

- 기존 목표 설정 UI의 위계·여백·문구를 "오늘의 러닝 → 목표 → 시작"으로 재배치
- 이번 주/지난 러닝/첫 러닝 요약 줄 제거
- 기록 데이터 미로딩 상태가 러닝 탭 문구를 바꾸지 않도록 의존성 제거
- 실기기 체크리스트에서 VoiceOver 항목 제거, 대기 화면 의도 일치 항목을 새 구조로 갱신

### 제외

- 5km·30분 같은 고정 프리셋 또는 목표 저장
- 기록 탭의 새 통계·추천·개인 최고기록
- 실제 GPS 정확도·배터리·달리는 중 조작감 검증
- VoiceOver 기능 추가 또는 접근성 UI 재설계
- 기록 탭 다크 배경과 차트 격자선 대비 보정 (현재 `history-tab` QA 보정 태스크 소유)

## 완료 기준

1. 앱을 재실행하거나 탭을 오가도 러닝 대기 화면의 내용이 기록 로딩 여부로 바뀌지 않는다.
2. 사용자는 첫 화면에서 자유·거리·시간 목표를 고르고 시작할 수 있다.
3. GPX 실기기 테스트로 목표 설정 → 시작 → 저장 → 기록 탭 반영을 다시 확인한다.
4. 사용자가 러닝 대기 화면을 보고 "무엇을 설정하고 어떻게 시작하는지"가 바로 이해되는지 직접 판정한다.

## 검증 전략

- 자동: 요약 줄 제거 뒤 러닝 탭의 목표 선택·입력·시작 회귀 테스트, 기록 탭 집계 회귀 테스트
- 시뮬레이터: 라이트/다크 모드와 큰 글자 크기에서 기록 탭·러닝 탭 렌더링 확인
- 실기기: 기존 5km·1분 페이스 GPX로 저장 경로를 반복하고, 대기 화면의 의도를 확인한다. VoiceOver는 이 마일스톤의 통과 조건이 아니다. 기록 탭 화면 대비는 현재 `history-tab` 보정 태스크에서 별도로 재확인한다.
