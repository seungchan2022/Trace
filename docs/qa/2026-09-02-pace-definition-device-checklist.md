# 페이스 두 지표 표시 실기기 체크리스트 (2026-09-02, GPX 재생 기준)

> 이제 러닝 화면과 잠금화면 모두에 페이스가 **"현재 페이스"와 "평균 페이스" 두 개**로 나뉘어
> 보입니다. "현재 페이스"는 최근 몇 초 동안의 속도만 반영해서 지금 얼마나 빠른지를 빠르게
> 보여주고, "평균 페이스"는 지금까지 뛴 전체 평균이라 1킬로미터마다 나오는 음성 안내가
> 말하는 숫자와 같습니다.

빌드/테스트는 전부 통과했습니다(자동 테스트 388개 전체 통과, 회귀 없음).

## GPX로 진행하는 방법과 이 파일의 타임라인

Xcode 스킴의 Run > Options > Location Simulation에서 `docs/qa/2026-09-02-pace-definition-steady-pace.gpx`를
선택해 위치 재생을 설정합니다(QA가 끝나면 공유 스킴이므로 다시 꺼두세요 — `testing.md` 참고).
기기를 연결하고 Xcode에서 Run을 누른 뒤, 앱에서 러닝을 "시작"하면 아래 시간표대로 자동으로
위치가 움직입니다(초 단위로 딱 맞춰져 있어서, 화면의 "시간" 표시를 보면서 다음에 뭐가 일어날지
미리 알 수 있습니다).

| 화면 시간 | 일어나는 일 |
|---|---|
| 0:00 | 러닝 시작 |
| 1:00 | 1km 도달 → 음성 안내 |
| 2:00 | 2km 도달 → 음성 안내 |
| 3:00 | 3km 도달 → 음성 안내 |
| 4:00 | 4km 도달 → 음성 안내 |
| 5:00 | 5km 도달 → 음성 안내 (완주) |
| 5:00~5:30 | 그 자리에 멈춰 있음 |
| 5:30 이후 | **되감아 처음부터 다시 재생됩니다 — 이 전에 반드시 종료할 것** |

**미리 알려드릴 것 하나:** 이 GPX 파일은 속도가 항상 똑같아서(등속), "현재 페이스" 칸이 계속
`--'--"`(빈 값)로 나올 가능성이 높습니다. 이건 GPX로 위치를 흉내 낼 때 속도 정보가 함께
들어가지 않아서 생기는, **이 시뮬레이션 방법만의 한계**입니다(실제로 뛸 때는 GPS가 속도를
주므로 문제없고, 계산 로직 자체는 자동 테스트로 이미 확인했습니다). 그러니 "현재 페이스"
숫자 자체가 안 보이는 것은 실패로 체크하지 마시고, 대신 **그 자리에 라벨과 빈 값 표시가
잘리지 않고 제대로 나오는지**만 봐주시면 됩니다.

**사용법:** 아래 순서대로 하나의 러닝으로 이어서 진행합니다. 각 확인 지점마다 통과/실패를
체크하고, 다르면 메모에 무슨 일이 일어났는지 적어주세요.

## 핵심 기능 (손으로 수행, 하나의 러닝으로 이어서)

### 시작 ~ 1km (0:00 ~ 1:00)

**수행:**
1. 러닝 탭에서 "시작"을 누른다.
2. 화면을 켠 채로 지켜본다.

**확인할 것 1:** "GPS 신호 찾는 중" 화면을 빠르게 지나 트래킹 화면(시간·거리·평균 페이스·
현재 페이스)으로 넘어가는가.

**결과:** ☐ 통과 ☐ 실패
**메모:**

**확인할 것 2:** 화면 아래쪽 보조 숫자 줄에 "시간·평균 페이스·현재 페이스" 세 라벨과 값이
잘리거나 겹치지 않고 다 보이는가(현재 페이스 값이 비어 있는 건 위에서 설명한 대로 정상입니다
— 라벨과 빈 칸 표시 자체가 잘리지 않는지만 보시면 됩니다).

**결과:** ☐ 통과 ☐ 실패
**메모:**

**확인할 것 3:** 화면 시간이 1:00 근처에 다다르면 "1킬로미터…" 음성 안내가 나오는가.

**결과:** ☐ 통과 ☐ 실패
**메모:**

---

### 잠금화면 확인 (1:00 이후, 화면을 잠근다)

**수행:**
1. 1km 안내를 들은 직후 전원 버튼을 눌러 화면을 잠근다.
2. 잠금화면 카드를 본다.
3. 2km 안내(화면 시간 2:00)가 나올 때까지 그대로 둔다.

**확인할 것:** 잠금화면 카드의 숫자·라벨(거리·시간·현재 페이스·평균 페이스)이 잘리거나
겹치지 않고 다 보이는가. 2km 안내가 나온 직후 카드에 보이는 "평균 페이스" 숫자가 방금 들은
음성 안내 숫자와 같은가.

**결과:** ☐ 통과 ☐ 실패
**메모:**

---

### 일시정지 확인 (2:00 ~ 3:00 사이)

**수행:**
1. 화면을 켜서 앱으로 돌아가 일시정지 버튼을 누른다. **잠금화면 카드에는 일시정지 버튼이
   없고 "포인트" 버튼만 있습니다** — 일시정지·재개는 앱 화면에서만 누를 수 있습니다.
2. 다시 화면을 잠그고 몇 초간 그대로 두고 잠금화면 카드를 본다.

**확인할 것:** 일시정지한 뒤에도 잠금화면 카드의 숫자·라벨이 잘리거나 겹치지 않아야 한다
(멈춘 시간 표시가 길어지는 지점이라 특히 좁아 보일 수 있습니다). 확인 후 앱으로 돌아가
재개 버튼을 눌러 계속 진행한다.

**결과:** ☐ 통과 ☐ 실패
**메모:**

---

### Dynamic Island 확인 (3:00 ~ 4:00 사이)

**수행:**
1. 러닝 중인 상태 그대로, 화면을 켜고 Dynamic Island(화면 위쪽 알약 모양 영역)를 길게
   눌러 확장한다.
2. 앱으로 돌아가 일시정지 버튼을 누른 뒤, 다시 Dynamic Island를 길게 눌러 확장한다.

**확인할 것 1 (러닝 중):** 거리·현재 페이스가 보이는가.
**여기서 시간만 보이고 거리·현재 페이스가 안 보이는 것은 실패로 체크하지 마세요** — 이건
이번 사이클 이전부터 있던 것으로 확인된 문제입니다(`docs/backlog.md` 참고).

**확인할 것 2 (일시정지 중):** 거리·시간·현재 페이스·평균 페이스가 잘리거나 겹치지 않고
다 보이는가. **여기서 실패하면(빈 화면이거나 일부만 보이면) 진짜 실패로 체크해 주세요.**

**결과:** ☐ 통과 ☐ 실패
**메모:**

(확인 후 앱으로 돌아가 재개 버튼을 눌러 계속 진행한다.)

---

### 완주 및 종료 (4:00 ~ 5:00, 그리고 5:30 전에 종료)

**수행:**
1. 화면 시간이 5:00에 다다르면 "5킬로미터…" 완주 음성 안내를 듣는다.
2. **화면 시간이 5:30을 넘기 전에** 종료 버튼(길게 누르기)을 눌러 러닝을 끝낸다. (넘기면
   위치가 처음으로 되감겨 거리가 이상하게 부풀어 오릅니다 — 그 전에 꼭 종료해주세요.)
3. 러닝 요약 화면을 확인한다.

**확인할 것:** 4km, 5km 지점에서도 음성 안내가 정상적으로 나왔는가. 요약 화면에 최종 거리가
대략 5km로 나오는가(등속이라 정확히 5.00km에 가까울수록 정상입니다).

**결과:** ☐ 통과 ☐ 실패
**메모:**

## 알려진 한계 (버그 아님)
- [ ] 이 GPX는 속도가 일정해서 "현재 페이스"가 실제로 채워지는 모습은 이 방법으로는 확인이
      어렵습니다(위에서 설명한 이유). 계산 로직 자체는 자동 테스트로 검증돼 있습니다.
- [ ] 신호를 기다리는 것처럼 완전히 멈춰 서 있는데 일시정지 버튼은 안 누른 채로 오래
      있으면, 평균 페이스 숫자가 잠깐 그 자리에 멈춰 있다가 다시 움직이면 정상으로 돌아오는
      경우가 있을 수 있습니다(이미 알려진 것이며 이번 작업 범위 밖입니다).
